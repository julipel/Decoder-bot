# Правила работы с репозиторием

## Ветки

- `main` — стабильная ветка; всегда в рабочем состоянии.
- `feature/<sprint>-<тема>` — рабочая ветка на одну задачу/тему спринта,
  например `feature/s1-project-bootstrap`, `feature/s1-telegram-adapter`.
- При работе одного разработчика допустимо упрощение до одной ветки на
  спринт: `feature/sprint-1`, `feature/sprint-2` и т. д.
- `develop` — опциональная интеграционная ветка; используется только при
  работе нескольких разработчиков одновременно.

Ветка спринта сливается в `main` по завершении спринта (или отдельная
feature-ветка — по завершении задачи).

## Коммиты

Формат сообщения — [Conventional Commits](https://www.conventionalcommits.org/):

```
<тип>: <краткое описание в повелительном наклонении>
```

Основные типы:

| Тип | Когда использовать |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление ошибки |
| `docs` | изменения только в документации |
| `chore` | вспомогательные задачи (настройка репозитория, зависимости, конфигурация) |
| `refactor` | изменение кода без изменения поведения |
| `test` | добавление/изменение тестов |
| `build` | изменения сборки/упаковки (`pyproject.toml` и т. п.) |

Пример: `chore: initialize dekoder repository`.

## Секреты

Реальные значения секретов (токены, ключи API, хеш пароля администратора)
никогда не коммитятся. Единственный файл с переменными окружения в
репозитории — `.env.example`, без значений (см.
[`docs/06_development_environment.md`](docs/06_development_environment.md), §4).
